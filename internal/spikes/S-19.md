# S-19 · CSS provenance (CSS modules on the Vite dev server)

> **Status:** slice half done (BUILD B-19). Container-only. Chromium 153.0.8010.12 (Playwright 1.63.0), Storybook 10.6.7, Vite 8.3.8, fixture `fixtures/ds-react`.
> **Question** ([14 S-19](../plan/14-roadmap.md#phase-0), [15 §5.1](../plan/15-change-requests.md#provenance)): do CDP `rule.styleSheetId` + `style.range` and the `CSS.styleSheetAdded` headers, with Vite dev source maps, give the original `file:line` and selector of each field a designer can change, and the `var()` chain down to each custom property's definition?
> **Answer for CSS modules (and the plain global CSS they use): yes.** Every author-declared field resolves to a verified location, with no wrong file. Plain CSS as its own styling approach, Tailwind v4, emotion and the `data-holotype-loc` prototype are the hardening half (§9).

## 1. Headline

On the dev server with `css.devSourcemap: true` (branch mode), over 46 ds-react stories with mapped fields, 180 captured nodes and 1,165 fields (light theme; the dark theme gives the same numbers):

| Measure | Result |
|---|--:|
| Fields resolved to a verified `file:line:col` and original selector | **1,123 / 1,165 (96.4%)** |
| … of the fields an author rule declares (no browser default, no initial value) | **1,123 / 1,123 (100%)** |
| `var()` chains located down to every definition (`tokens.css`, `:root` or `[data-theme="dark"]`) | **900 / 900 (100%)** |
| Wrong file or wrong line (ground-truth check fails) | **0** |
| Wrong original selector | **0** |
| Winner that does not explain the computed value | **0** (1,154 match, 11 not comparable) |
| Source-map segments that start exactly at the declaration | 1,123 / 1,123 |
| Captured elements not found in the live DOM | 0 |

The 42 unresolved fields have no CSS location to give: 36 are the user-agent `padding-block: 1px` of `<button>` (Button, and Buttons inside Card and Stack), and 6 are an initial `font-weight` (400) on text no rule styles.

## 2. Method

1. **Dev server.** `startDevServer()` runs `storybook dev` for the fixture on a free `127.0.0.1` port. The fixture's `.storybook/main.ts` already sets `viteFinal → css.devSourcemap: true` (checked; `fixtures/**` not edited). For the no-map run, a generated config directory under the fixture's `node_modules` reuses `main.ts` and `preview.tsx` with `devSourcemap: false`.
2. **Capture.** `createCapturer` from `@holotype/capture` (Playwright + CDP, D-24 environment, 1 worker) captures each `components-*` and `micro-*` story opted in to Figma (52 stories; 6 have no mapped field). Its `preparePage` hook attaches the probe: a CDP session with `DOM.enable` + `CSS.enable` before the first navigation, so every `CSS.styleSheetAdded` header is seen.
3. **Locate.** Each Capture IR element is matched to a DOM element under `#storybook-root` in document order by tag, classes and border box (0 misses). A text node takes its container element.
4. **Fields.** `relevantFields()` picks the longhands that become Scene fields: non-zero padding, flex/grid gaps, a visible background, border widths and visible colors, non-zero radii, and for text `color`, `font-family`, `font-size`, `font-weight`, `line-height` (and `letter-spacing` when set).
5. **Resolve** (`spikes/S-19/resolver`, pure): `CSS.getMatchedStylesForNode` → the cascade winner per longhand (shorthands by a name table, logical properties by direction, inheritance through `inherited[]`, `!important`, `inherit`) → sheet table (header + owner `data-vite-dev-id` + decoded inline map) → `traceSegment` of the declaration's `range` start → repo-relative `SourceLoc` (1-based), validated inside the repo. The original selector is read from the map's `sourcesContent` at the mapped selector start. `var()` chains follow each custom property from the level where the previous one was declared.
6. **Ground truth** (`oracle.ts`, independent of the map): the repo file must hold, at the reported line and column, a declaration of the winning property, inside a rule whose selector list contains the reported original selector; each definition location must hold `--name:`. A failure counts as **wrong file**. A second check compares the winner's literal (or chain terminal) with the computed value.
7. **Modes.** `dev` (maps on, light and dark), `no-sourcemap` (dev server, maps off), `static` (built Storybook).

Run it: `pnpm build && pnpm -F @holotype/spikes s19` (writes `spikes/S-19/results/summary.json`, about 90 s). Tests: `pnpm -F @holotype/spikes test` (resolver unit tests on a recorded CDP fixture of `components-button--primary`) and `pnpm -F @holotype/spikes test:e2e` (the dev server, both map modes).

## 3. What Chromium and Vite actually give

These facts differ from the plan text (see §8, plan gaps).

| Sheet | `isInline` | `sourceURL` | `sourceMapURL` | `ownerNode` attrs | Ranges |
|---|---|---|---|---|---|
| Vite dev CSS (`*.module.css`, `tokens.css`, `base.css`) | `false` | `""` | inline map as a `data:` URL | `data-vite-dev-id` = absolute file path | relative to the sheet, `startLine` 0 |
| Storybook `iframe.html` inline `<style>` | `true` | the document URL | some have one; its source is the virtual `\0/iframe.html` | none | **relative to the sheet**, although `startLine` is 15 or 69 |
| Storybook preview injected styles | `false` | `""` | none | none | relative to the sheet |
| Static build CSS (`<link>`) | `false` | `http://…/assets/*.css` | none | none | relative to the sheet |

- **Ranges are sheet-relative for every sheet**, inline `<style>` included: a selector at document line 117 of `iframe.html` comes back as line 48 of a sheet whose `startLine` is 69. DevTools adds `startLine` to show document positions. Nothing is subtracted; `documentPosition()` adds the offset when a document position is wanted.
- Vite inserts dev CSS with JavaScript, so Chromium does not treat it as inline. The map is in the header (`sourceMapURL`), and `data-vite-dev-id` is the file. Map sources are absolute paths.
- Vite's CSS-module transform keeps line and column numbers: hashed classes `._md_xefp9_64` (`_<local>_<hash5>_<line>`) sit where `.md` was. The static build uses the same class names.
- No component node matched a Storybook preview sheet: the capture's fullscreen layout override keeps them out.

### 4.5 Cost

`CSS.getMatchedStylesForNode` takes **7–9 ms per element** here (178 calls per pass), 3–4× the 1–3 ms of [05 §6.2](../plan/05-capture.md#authored): each response repeats the ancestors' rules, including the `:root` token rule (about 120 custom properties). The pure resolver costs about 0.1 ms per field. The memo by match signature that 05 §6.2 plans matters; see §7.

## 5. Failure modes

| Failure | Seen | Behaviour now | Remedy |
|---|--:|---|---|
| User-agent default (button `padding-block: 1px`) | 36 | `unresolved: user-agent`, valid winner | Not a missing location: there is no rule. DCR should say where to add one (§6) |
| Initial value (no rule declares it) | 6 | `unresolved: not-declared` | Same as above |
| Sheet without map, with `data-vite-dev-id` | all, in `no-sourcemap` | `approximate`: dev-id file, served line | Exact for Vite CSS modules and plain CSS; wrong as soon as a PostCSS step adds or removes lines (nesting, `@import` inlining, Tailwind). Warn |
| Sheet without map and without dev id (inline `<style>`, CSS-in-JS, constructed) | 0 on components | `unresolved: no-sourcemap`, served selector only | `DCR_PROVENANCE_NO_SOURCEMAP` |
| Built CSS (static build) | all, in `static` | `selector-only`, de-hashed by pattern | `DCR_PROVENANCE_MINIFIED`; capture from the dev server |
| Map source outside the repo, in `node_modules` or virtual (`\0/iframe.html`) | 0 on components | `unresolved: outside-repo / dependency / virtual` | Never reported as a location: the path check rejects it |
| `style=""` (React `style` prop) | 0 | `unresolved: inline-style` | Needs the JSX location (`data-holotype-loc`, hardening) |
| Several `var()`s in a longhand (`calc(var(--a) + var(--b))`) | 0 | chain `ambiguous` | Not provable (D-18): no binding, an open question |
| Non-positional shorthand with several `var()`s (`outline: var(--w) solid var(--c)`) | 0 | the reference whose chain terminal equals the computed value; else `ambiguous` | — |
| A `var()` that expands to several values (`padding: var(--pad)`, `--pad: 4px 8px`) | 0 | wrong component possible; the value check flags it as `mismatch` | Gate on `valueCheck` |
| Not modelled: cascade layers with `!important`, user-agent `!important`, `all`, `revert-layer`, vertical writing modes | 0 | — | Hardening, with a fixture each |

Locating captured nodes by geometry is a spike shortcut (0 misses here); B-45 should use the serializer's own element handles (§7).

## 6. Proposed thresholds and diagnostics

| Code | Proposal |
|---|---|
| `DCR_PROVENANCE_MISSING` (warn) | Per DCR field whose winner is an author declaration but which has no `rule` and no JSX `loc`. **Not** for user-agent or initial values: those get `FieldOrigin.default: 'user-agent' \| 'initial'` and a suggested place (the node's own nearest author rule, e.g. `.button` in `Button.module.css`), so the prompt can say "add `padding-block` to `.button`". Run level: one summary warning per component when located / author-declared fields < **95%** (measured 100% on ds-react) |
| `DCR_PROVENANCE_NO_SOURCEMAP` (warn) | Once **per file** (dedupe by dev id or URL, not by `styleSheetId`: each navigation adds new sheets), raised lazily, only for sheets that hold a winning declaration or `var()` definition of a mapped field, so Storybook's own sheets never warn. Two cases in `data`: `approximate: true` (dev id, served lines kept, flagged in the prompt as "line may be off") and `approximate: false` (no file: selector only). When more than half of the contributing files lack maps, one aggregated warning ("`css.devSourcemap` looks off for this project") instead of one per file |
| `DCR_PROVENANCE_MINIFIED` (info) | Once **per capture run** with `data.files` (measured 9 per static run; one fact, not nine) |
| CI gate for B-45/B-51 fixtures | wrong file **= 0**, wrong selector **= 0**, value mismatch **= 0**, chains located **= 100%** of `var()` fields, author-declared located **≥ 99%** |

## 7. Recommendations

### B-45 (`capture`: matched styles, `var()` chains, rule locations)

1. **Move `spikes/S-19/resolver/` as is** (pure, no Node built-ins: `atob`, `TextDecoder`; one dependency, `@jridgewell/trace-mapping@0.3.31`): `cdp.ts`, `cascade.ts`, `longhands.ts`, `var-refs.ts`, `var-chain.ts`, `values.ts` become `src/cdp/matched/*`; `sheets.ts`, `paths.ts`, `css-text.ts` become `src/cdp/sourcemap/*`; `resolve.ts`, `fields.ts`, `diagnostics.ts` stay together. Bring the tests and `test/fixtures/button-primary.json` (re-record with `s19:record`).
2. **No range offsets.** Use CDP ranges as sheet-relative positions with the sheet's own map.
3. **Sheet table.** Listen to `CSS.styleSheetAdded` and `CSS.styleSheetRemoved` from `CSS.enable`, which must run before the first navigation (`preparePage` or the worker's own session). Read `data-vite-dev-id` with `DOM.describeNode({ backendNodeId: header.ownerNode })` lazily and cache per `styleSheetId`; decode `data:` maps; fetch linked maps from `127.0.0.1` only.
4. **Do not put maps in `CaptureDoc`.** The `tokens.css` map alone is about 28 kB as a `data:` URL, in every capture. Resolve to `SourceLoc` in the orchestrator right after the capture, cached per (dev id, sheet text hash), and store in `CaptureDoc.styleSheets` only `sourceURL`, `sourceMapURL` (never a `data:` URL), a repo-relative `devId` and the sheet kind. This needs an `ir:` schema PR before B-45.
5. **Node ids.** Have the serializer hand back element handles in `CNode` order (`DOM.requestNode`), instead of the spike's geometry matching.
6. **Fields.** Take the field set from the Capture IR (`computed` padding, border, radius, background; `flex` gaps once B-41 adds them; `CTextStyle` for text) instead of a second `getComputedStyleForNode` call.
7. **Cost.** Memoize matched styles by match signature as 05 §6.2 plans, and fetch each element once (text nodes reuse their container's response). Budget 10 ms per call, not 1–3 ms.
8. **Acceptance.** `components-button--primary` `padding-left` resolves to `--space-4` (not `--space-3`: `.md` uses `--space-4`) at `Button.module.css:67:3`; `background-color` resolves through `--button-bg` → `--color-primary` → `--color-blue-600`.

### B-51 (`mapper`: exact tokens and provenance)

1. Build each `FieldOrigin` with `toFieldOrigin(field, css)`. For D-16 border-included padding, pass `css: ['border-left-width', 'padding-left']` and keep the padding's `rule`; the border width has its own resolved field for reverse arithmetic.
2. Bind variables only from `varChain.pure` chains (all 900 here are pure). `varChain` is the name list; keep each step's definition `SourceLoc` (15 §5.4 has a single `varDefinition`; the designer usually rebinds the first name, but the agent may need any step).
3. Add `default: 'user-agent' | 'initial'` to `FieldOrigin` for winners with no author rule (an `ir:` PR), with the suggested rule location (§6).
4. B-51's acceptance "Button `paddingLeft` binds `space/3`" holds for `Size=sm` only; `Size=md` binds `space/4`.
