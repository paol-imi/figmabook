# 11 — UX: CLI, configuration, plugin, generated artifacts

> Scope: everything a human (or agent) touches. The config **schema** is owned by [16](16-config.md) (D-51); the wire protocol by [02](02-architecture.md); reconciliation semantics by [10](10-sync.md). This chapter fixes the *user-facing* surface: commands, flags, exit codes, screens, copy, and what lands in the Figma file. It owns the command registry ([§3.3](#commands)), the exit codes ([§3.2](#exit-codes)) and the status vocabulary ([§7.7](#status-vocabulary)).
>
> **Naming.** The product is **Holotype** in all UI copy and prose. Lowercase `holotype` appears only in commands, package names and code.

## 1. Personas and jobs-to-be-done

| Persona | Context | Jobs-to-be-done | What they must never experience |
|---|---|---|---|
| **DS engineer** (primary installer) | Owns the Storybook, comfortable with Node/CI | "Get our components into Figma without redrawing." "Know exactly what didn't convert and why." "Make it run on every release." | Opaque failures; having to restructure stories just for the tool; credentials leaving the machine (G7) |
| **Product designer** (primary consumer) | Uses the published library; edits instances | "Use real components with sensible properties." "Keep my overrides when the library updates." | Overrides wiped; 2,000-variant sets; layers named `div` |
| **Design-ops / library maintainer** | Owns the Figma library file, publishes it | "Review what changed before it lands." "Protect hand-made annotations." "Decide what's deprecated." | Silent overwrites; deleted components breaking files (D-20) |
| **CI / agent** | GitHub Action, MCP client | "Produce a bundle deterministically from `storybook-static`." "Report fidelity on the PR." "Sync component X on request." "Implement the design change request, then prove it" ([15](15-change-requests.md#agent-contract)). | Interactive prompts; non-zero exit without machine-readable reason; vague specs |
| **Reviewer** (lead, boss) | Opens the branch file in the desktop app; no CLI | "See what is being asked before any AI starts." "Approve it in one click." | JSON, file paths, or a wall of items with no summary |

Branch files are edited by designers; developers may edit too. The designer view is the default; code details sit behind **Show code details**.

Design principles derived from these:

1. **Zero-config first run, full control later.** `init` writes a working config by inspecting the Storybook; everything else is optional.
2. **Never surprise the library.** Every write is previewed ([10](10-sync.md)); defaults are conservative (deprecate, don't delete; keep designer edits on conflict by default — see §6.7).
3. **Explain every loss.** Every approximation yields a diagnostic with a docs link ([12](12-quality.md#diagnostics)); the plugin can select the offending node.
4. **Same behaviour, every surface.** CLI, plugin, Action and MCP call the same packages; options have the same names everywhere.

## 2. End-to-end flows

### 2.0 Installing the plugin (D-39) <a id="install"></a>

Distribution is private. No Community listing until after M8.

**Now: development plugin** (the user and their boss; any Figma plan, no review). Each release ships `holotype-plugin-<version>.zip`. The boss needs only the Figma desktop app: no Node, no CLI, no terminal.

1. Get `holotype-plugin-<version>.zip` from the delivery channel: a GitHub release asset, or the owner sends it.
2. Open it. It contains one folder, `Holotype Plugin/`. Move that folder to Documents.
3. In the Figma **desktop app**: main menu ▸ **Plugins ▸ Development ▸ Import plugin from manifest…**. Pick `Holotype Plugin/manifest.json`.
4. Run **Plugins ▸ Development ▸ Holotype**.

- **Updating.** Drag the new `Holotype Plugin` folder to Documents and choose **Replace**. No re-import. Figma reloads the code from disk on the next run. Settings and file data survive, because the manifest `id` never changes ([02](02-architecture.md)).
- **Version.** The Settings footer shows "Holotype plugin 0.4.1". When the paired CLI or the release feed reports a newer version, a banner reads "Holotype 0.5.0 is available. [How to update]".
- **Without the CLI.** The boss can use **Import file** (§2.3) on a `.holotype.zip` the user sends, or just open the library file that the user has already synced.
- Import and run the dev plugin in the desktop app; the browser app does not offer development plugins reliably ([02](02-architecture.md)).

**Later: private organization plugin**, once the plugin is stable. An admin publishes it to the organization only (no Figma review). Org members then find it among the organization's plugins in **Resources ▸ Plugins** and click **Run**. There is nothing to import, and updates arrive automatically. Dev-plugin users remove the development copy.

### 2.1 First run (developer)

**Entry point:** `npx @holotype/cli@latest init` (or `npm create holotype@latest`). `init`:

1. detects Storybook (`package.json`, `.storybook/`), its version, framework and addons (themes, pseudo-states);
2. pings the dev server on :6006, or offers `storybook build`;
3. installs the pinned Chromium with progress ("Downloading Chromium (≈170 MB)…");
4. adds `@holotype/cli` as a devDependency and a `holotype` script to `package.json`;
5. writes `holotype.config.ts`;
6. writes the three `.gitignore` lines of [02 §5.4](02-architecture.md#workspace) (`.holotype/*`, `!.holotype/requests/`, `!.holotype/branches/`) and self-checks them;
7. prints a `doctor` summary.

Later copy uses `pnpm holotype …` (or the project's package manager).

**Slice flow (topology B, D-10).** This is the default path.

```
DS engineer                          CLI                                    Figma plugin (desktop app)
───────────                          ───                                    ─────────────────────────
pnpm holotype capture ──────────►  render ▸ capture ▸ map
                                    write .holotype/out/<runId>.holotype.zip
                                    + report.html
                                                                         Plugins ▸ Development ▸ Holotype
                                                                         Import file ▸ pick <runId>.holotype.zip
                                                                         Fonts preflight: 2 missing → map or substitute
                                                                         Diff preview (first import = all "Create")
                                                                         Apply ▸ progress per component
                                                                         Report: 3 warnings, fidelity 0.991
```

**Pairing flow (topology A, hardening).** The plugin talks to a local server instead of importing a file ([02 §3](02-architecture.md#pairing)).

```
DS engineer                          CLI                                    Figma plugin (desktop app)
───────────                          ───                                    ─────────────────────────
pnpm holotype serve ────────────►  start loopback server 127.0.0.1:47321 (D-25)
                                                                         Plugins ▸ Development ▸ Holotype ▸ Connect
                                    ◄── POST /v1/pair/start ──────────────
                                    print PAIRING CODE  482 913
                                                                         enter code ──► token stored in clientStorage
                                    ◄── GET /v1/session (caps, IR version) ──

                                                                         select ☑ Button ☑ Input ☑ Card
                                    ◄── POST /v1/runs {components, configOverrides}
                                    capture ▸ map ▸ stream component.ready events ──►
                                                                         fetch chunks ▸ fonts preflight ▸ diff ▸ apply
```

**Time to first component.** Target **< 5 minutes** on a typical React + Vite Storybook 10 (D-26; tracked in usability tests, [12](12-quality.md)). It is measured from the start of `init`, with the Chromium download excluded and reported separately.

### 2.2 Update flow (re-sync with diff and conflicts)

1. Plugin opens → reads registry from `figma.root` shared plugin data → compares it with the current component hashes (`GET /v1/manifest` when paired, or the imported bundle's manifest) → component browser marks **Outdated** components (chip).
2. User selects Outdated (or "Select all outdated") → **Re-sync**.
3. CLI recaptures only changed variants (capture cache, [02](02-architecture.md)); mapper produces Scene IR; plugin computes the **apply plan** read-only.
4. **Diff preview** (§6.6): per component: variants added/changed/removed, property changes, token changes, visual before/after; plus **Conflicts** (managed nodes whose `ah` ≠ current hash, i.e. designer edits, [10](10-sync.md)).
5. User resolves conflicts (per node or bulk policy: *Keep mine* / *Take code* / *Fork* / *Lock*, §6.7), then **Apply**.
6. One undo step per component (`figma.commitUndo()` boundaries); report shown; registry updated. Designer then publishes the library (manual — Figma has no publish API; the plugin reminds them).

### 2.3 File-import flow (topology B — always available)

`pnpm holotype capture` writes `.holotype/out/<runId>.holotype.zip`; `pnpm holotype export --file button.holotype.zip` re-packages a cached run (or download the CI artifact) → plugin **Import file** tab → drag & drop or file picker → manifest validated (IR major, generator) → same browser/preflight/diff/apply path as 2.1/2.2. No network required; this is the documented fallback whenever LNA or a corporate proxy blocks loopback (§6.10).

### 2.4 CI flow (topology D, hardening)

```yaml
- run: npx storybook build -o storybook-static
- uses: holotype/action@v1
  with:
    storybook: storybook-static
    publish: artifact            # 'registry' | 'pages' once the registry ships
    fidelity-report: true        # PR summary + annotations
```

The Action runs `holotype capture --static storybook-static --json` → bundle + `report.json`. The CI artifact is the un-nested `.holotype.zip`, and the PR summary links **Download for Figma** (file import, D-10). The PR comment lists components changed, variants changed, diagnostics delta and fidelity delta. Once a registry exists, the Action also publishes a `latest.json` pointer, and designers see **Outdated** the next time they open the library file.

### 2.5 Agent / MCP flow (server + DCR tools in hardening H-E; sync tools in Phase 7)

`holotype mcp` (stdio) exposes tools: `list_components`, `plan_component` (returns proposed axes/properties), `capture` (returns bundle path + summary), `report`, the DCR tools (§2.6), and — experimental, S-11 — `apply_via_use_figma`. Typical agent loop: "sync Button to Figma" → `plan_component` → `capture` → hands the bundle to the user's plugin (or to Figma MCP `use_figma` if S-11 succeeds). Agents get JSON summaries, never raw Scene IR, to stay inside context limits.

### 2.6 Design change request flow (Phase 4.5) <a id="dcr-flow"></a>

The full workflow is in [15](15-change-requests.md).

<a id="handoff"></a>**Two machines are the primary case.** The designer works on their own Mac (Figma desktop app, plugin unpaired). The developer works on another machine (repo, CLI, agent). Nothing needs the two to be connected. Mechanics are in [15](15-change-requests.md#handoff).

**Canonical order** (every chapter and screen uses it): **Changes → Review & submit** (Scope, Preview, Send) **→ (reviewer) Approve** [hardening].

```
Developer's machine (repo, CLI)              Designer's Mac (Figma desktop, plugin)          Agent
───────────────────────────────              ──────────────────────────────────────          ─────
holotype branch start ──► capture dev server,
  link branch file (--figma <branch url>)
  apply in proposal mode ───────────────────► baseline + branch:meta
                                              designer edits · Changes (§6.14)
                                              Review & submit: Scope ▸ Preview ▸ Send (§6.15)
                                              plugin writes the request into the file,
                                              saves a version
                                              Notify developer (copies message)
                                              or Download request (.zip)
holotype dcr --pull <figma-url>  ◄──────────  (message / chat / email)
  or holotype dcr import <file.zip>
write .holotype/requests/<id>/  ──────────────────────────────────────────────────────────► design_changes
                                                                                            implement + stories
holotype verify  ◄──────────────────────────────────────────────────────────────────────── (agent runs it)
holotype branch refresh ──► re-sync: implemented items disappear from Changes
holotype branch close   ──► status: merged; archive instructions (below)
```

Steps:

1. The designer presses **Submit** in Review & submit.
2. The plugin writes the request into the file and saves a version.
3. The designer picks **Notify developer** (copies the message below) or **Download request (.zip)**.
4. The developer runs `holotype dcr --pull <figma-url>` or `holotype dcr import <file.zip>`. Either writes `.holotype/requests/<id>/`.
5. The agent implements the request ([15 §8](15-change-requests.md#agent-contract)), then runs `holotype verify`.

<a id="notify-developer"></a>**Notify developer message** (copied to the clipboard):

> Design request a41c09e2 is ready on branch feat/price-tag. In the repo, run `holotype dcr --pull <branch URL>` (or `holotype dcr import <file>` with the attached request). Figma: <branch URL>

In the loop slice (before `--pull` ships) the message says `holotype dcr import <file>`, and **Download request (.zip)** is the primary action.

**Branch close.** `holotype branch close` prints, and the plugin shows on the branch file:

> Code is now the source of truth. In Figma, open the branch ▸ ⋯ ▸ Archive branch. Don't merge it: the main library updates from code when a maintainer re-syncs. Library maintainer: open the main file ▸ Holotype ▸ N Outdated ▸ Re-sync ▸ Publish.

A **Copy release notes** action copies the implemented items as a list ([15](15-change-requests.md#close)).

**Flow states (D-40):**

| State | Shown when | UI (title / body / actions) |
|---|---|---|
| **Empty** | nothing changed in the branch file | Changes empty state (§6.14) |
| **Loading** | Submit is writing the request and saving the version | "Saving request a41c09e2…" with progress; the canvas stays usable |
| **Error** | the version could not be saved, or the file is read-only | "Couldn't save the request in this file." / "Download it instead and send it to your developer." / [Download request (.zip)] [Retry] |
| **Success** | request written | "Submitted · a41c09e2." / "Your developer can pick it up with `holotype dcr --pull`." / [Notify developer] [Download request (.zip)] |

**MCP tools** (same names and payloads as [15 §7.1](15-change-requests.md#prompt)):

| Tool | Input | Output |
|---|---|---|
| `design_changes` | `{ id?, figmaUrl?, latest? }` | `{ id, summary, approval, promptMd, changedSinceSubmit }`. Defaults to the latest submitted request for the current git branch. The review summary always; the items only if approval isn't required, or this hash is approved |
| `dcr_item` | `{ id, itemId }` | one item's JSON (screens include variants, snippet, interactions, a11y) |
| `dcr_item_assets` | `{ id, itemId }` | before/after PNGs as image content |
| `verify_dcr` | `{ id }` | per-item status, as in `verify.json` |
| `list_dcrs` | `()` | `[{ id, branch, createdAt, counts, status }]` from `.holotype/requests/` |

## 3. CLI design (`holotype`)

### 3.1 Conventions

- Binary `holotype` (alias `holo`), package `@holotype/cli`. Node ≥22.12 (D-03, D-53).
- Global flags on every command:

| Flag | Meaning |
|---|---|
| `-c, --config <path>` | config file (default: search `holotype.config.{ts,mts,js,mjs,json}` upward) |
| `--storybook <url\|dir>` | override `storybook.source` |
| `--json` | single JSON document on stdout at exit (human logs → stderr) |
| `--ndjson` | stream events (`{type, ...}`) on stdout; for CI/agents |
| `--log-level <silent\|error\|warn\|info\|debug\|trace>` | default `info` |
| `--no-color`, `--no-progress` | auto-disabled when `CI=true` or not a TTY |
| `--cwd <dir>` | working directory |
| `-y, --yes` | accept defaults, never prompt (implied when not a TTY) |

- **Never prompt** when stdin is not a TTY or `--yes`/`CI` is set; missing required input → exit 2 with a diagnostic.
- Human output uses a single live progress region (component ▸ variant counters, ETA) + a final summary table; warnings are grouped by code with counts, `--log-level debug` expands.

### 3.2 Exit codes <a id="exit-codes"></a>

This table is canonical; [02](02-architecture.md) and the other chapters link here.

| Code | Meaning |
|---|---|
| 0 | Success (warnings allowed) |
| 1 | Completed with **errors** in some components (partial bundle written; see report) |
| 2 | Usage/config error (invalid flags, schema validation of config failed) |
| 3 | Storybook unreachable / index not loadable (`SB_INDEX_UNREACHABLE`, `SB_PREVIEW_INIT_TIMEOUT`) |
| 4 | Browser/Playwright failure (Chromium missing, crashed) |
| 5 | Quality gate failed (`--fail-on`, fidelity threshold, budget exceeded) |
| 6 | Network/auth failure (registry, login) |
| 130 | Interrupted (SIGINT); partial cache kept |

DCR commands reuse these codes:
- `verify` exits 0 only if every item is `implemented`, `declined` or `not-verifiable`; otherwise 5.
- `dcr` exits 5 on `DCR_NOT_APPROVED`, and 6 when the Figma token is missing or rejected.

| Diagnostic | Exit code |
|---|---|
| `DCR_NOT_BRANCH_FILE` | 2 |
| `DCR_GIT_BRANCH_MISMATCH` | 2 |
| `DCR_NO_SUBMITTED_REQUEST` | 2 |
| `DCR_NOT_APPROVED` | 5 |
| `NET_FIGMA_TOKEN_MISSING` | 6 |

### 3.3 Commands <a id="commands"></a>

This table is the single command registry; every chapter links here. Rows marked *(hardening)* are not in the loop slice ([14](14-roadmap.md#hardening)).

| Command | Purpose | Key flags |
|---|---|---|
| `init` | Inspect project; write `holotype.config.ts`; install pinned Chromium; add `@holotype/cli` and a `holotype` script; write exactly these `.gitignore` lines: `.holotype/*`, `!.holotype/requests/`, `!.holotype/branches/` ([02 §5.4](02-architecture.md#workspace); DCRs are committed, D-37) and self-check them; optional addon install | `--framework`, `--source <url\|dir>`, `--with-addon`, `--force` |
| `doctor` | Environment & Storybook health checks (§3.4) | `--fix` (safe fixes only), `--json` |
| `install-browser` | Download the pinned Chromium (D-05); `init` runs it | `--force` |
| `list` | List components/stories with planned axes & properties | `--include/--exclude <glob>`, `--plan` (show classification), `--only <sid>`, `--tree` |
| `capture` | Render + capture + map; writes the bundle to `output.dir` (`.holotype/out/<runId>.holotype.zip`) and `report.html` | `--only <sid,...>`, `--story <id>`, `--static <dir>`, `--no-cache`, `--trust-dev-cache` ([05 §10.2](05-capture.md#determinism)), `--concurrency <n>`, `--states`, `--themes`, `--viewport <WxH>`, `--debug-capture` (keep Capture IR + screenshots), `--fail-on <warn\|error>`, `--budget <n>` |
| `export` | Re-package a cached run as a bundle, without re-rendering | `--file <path.holotype.zip>`, `--only <sid,...>`, `--check-plugin-compat` (refuse a bundle the released plugin can't read, [02](02-architecture.md)) |
| `serve` *(hardening)* | Loopback server for the plugin (topology A, [02 §3](02-architecture.md#pairing)) | `--port <p>` (one of the manifest ports, D-25), `--watch` (re-capture on Storybook HMR / index change), `--revoke` (invalidate all sessions), `--pair-url` (print a one-time pairing URL instead of a code) |
| `login` | Store credentials: **private Storybooks** (headed browser login → Playwright `storageState` in `.holotype/auth/storageState.json`), the registry, and the **Figma token** for DCR reads (OS keychain, read-only scope, [13 §3](13-security-legal.md#secrets)). Replaces `auth login` | `login [--storybook <url> \| --figma \| --registry]`, `--headed` (default), `--logout`. `--figma` prompts for a token on a TTY, never argv |
| `branch start` | On a git feature branch: capture from the dev server, then link a Figma branch file and apply it in proposal mode ([15 §2](15-change-requests.md#branch-model)) | `--figma <branch-or-file url>` (skip the link prompt), `--dev-server <url>`, `--only <sid,...>` |
| `branch link` | Link an existing Figma branch or duplicated file to the current git branch | `<figma-url>`, `--kind figma-branch\|duplicate` |
| `branch refresh` | Re-sync the branch file from branch HEAD; baseline moves forward; implemented items disappear | `--only <sid,...>` |
| `branch status` | Show the link and how far code has moved. Prints "Code is N commits ahead of this branch file's baseline" | `--json` |
| `branch close` | Mark `status: merged`; print the close copy of [§2.6](#handoff) ("Code is now the source of truth…") and offer **Copy release notes** | `--archive` |
| `dcr` | Read the submitted request and write `.holotype/requests/<id>/` ([15 §7.1](15-change-requests.md#prompt)) | `dcr [--pull] [<figma-url>]` (`--pull` reads the request saved in the file; default: the linked file), `--scope changed\|ready\|page:<name>\|all` (default `changed`), `--part all\|components\|screens`, `--out <dir>`, `--with-comments`, `--format json,md`, `--split`, `--reextract` (REST re-extraction at `versionId`, hardening) |
| `dcr import` | Import a downloaded request | `dcr import <request.zip>` |
| `dcr prune` | Delete old requests from `.holotype/requests/` | `--keep latest` |
| `verify` | Regenerate from HEAD and check each DCR item ([15 §9](15-change-requests.md#verify)) | `verify [--dcr <id>]` (default: `LATEST-<branch-slug>`), `--screens`, `--decline <itemId> --reason <text>`, `--json` |
| `publish` *(hardening)* | Publish a bundle and the `latest.json` pointer | `--to <url\|s3://…\|gh-pages>` |
| `status` *(hardening)* | Compare a library file with the current Storybook (REST read) | `--figma-file <key>` |
| `prune` | List deprecated components older than `sync.pruneAfterDays` for removal (harness; [10](10-sync.md)); the plugin equivalent is "Prune deprecated…" | `--json` |
| `telemetry` | Show or change telemetry (D-23) | `telemetry status\|enable\|disable` |
| `mcp` *(hardening)* | MCP server over stdio for agents (§2.5) | `--allow-apply` (enables experimental use_figma tool) |
| `codeconnect` *(hardening)* | Generate Figma Code Connect files from the last `ApplyReport` ([06](06-ir.md#apply-report)) | `--map <holotype-map.json>`, `--out <dir>`, `--framework react\|html` |
| `cache` | Inspect/prune the content-addressed cache | `cache ls`, `cache prune [--older-than 14d]`, `cache clear`, `cache stats` |

**`verify` output** ends with the next step, for example:

```
2 partial → follow-up written to .holotype/requests/9b…/prompt.md.
Give it to your agent, then run holotype verify.
```

**`dcr` errors** name the fix:

| Situation | Message |
|---|---|
| no file linked on this machine | "No Figma file is linked to <branch> on this computer. Run `holotype branch link <url>`." |
| git branch differs (`DCR_GIT_BRANCH_MISMATCH`) | "Run `git switch <branch>`, then retry. Or download the request." |
| nothing submitted (`DCR_NO_SUBMITTED_REQUEST`) | "Nothing was submitted from this file yet. Ask the designer to press Submit." |
| no Figma token (`NET_FIGMA_TOKEN_MISSING`) | "Holotype needs a read-only Figma token. Create one in Figma ▸ Settings ▸ Security ▸ Personal access tokens (scope: File content, read), then run `holotype login --figma`." |

### 3.4 `doctor` checks

| # | Check | Failure → hint |
|---|---|---|
| 1 | Node version ≥22.12 | upgrade |
| 2 | Playwright + pinned Chromium present (D-05) | `holotype install-browser` |
| 3 | Config file valid (TypeBox schema, [16](16-config.md#validation)) | prints JSON-pointer errors |
| 4 | Storybook reachable; `index.json` (or `stories.json`) loads | `SB_INDEX_UNREACHABLE`; suggest `storybook build` |
| 5 | Storybook version in support matrix (D-11) | `SB_VERSION_UNSUPPORTED` for 7.x and older; best-effort warning for 8.x/9.x; info for non-React-Vite renderers (D-26) |
| 6 | Preview initializes (`__STORYBOOK_PREVIEW__.ready()`) within timeout | `SB_PREVIEW_INIT_TIMEOUT` |
| 7 | Dev server host validation / `allowedHosts` / CSP (only matters for non-localhost) | config snippet |
| 8 | SB11 `docgenServer`: component manifest present in static build | `SB_DOCGEN_DEGRADED`; suggest static build |
| 9 | Addons detected: themes, pseudo-states, viewport; `globalTypes` toolbar items | info |
| 10 | Sample render of 3 stories: errors, render time, fonts loaded | `SB_STORY_ERROR`, `FONT_LOAD_FAILED` |
| 11 | Web fonts used vs. common Figma availability (Google Fonts list heuristic) | early `FONT_MISSING` forecast |
| 12 | Ports 47321–47323 free on loopback | `NET_PORT_IN_USE` |
| 13 | Cache dir writable, size | `cache prune` |
| 14 | Auth: stored `storageState` age / expiry | `holotype login` |
| 15 | Telemetry status and `DO_NOT_TRACK` (D-23) | info |

`--fix` only performs: writing the three `.gitignore` lines (§3.3 `init`), installing pinned Chromium, writing missing config defaults.

## 4. `holotype.config.ts` <a id="config"></a>

The schema and defaults are in [16 §3](16-config.md#reference), and the full annotated example in [16 §20](16-config.md#example) (D-51). This chapter does not restate them. The most common keys:

```ts
// holotype.config.ts
import { defineConfig } from '@holotype/cli/config';

export default defineConfig({
  storybook: { source: './storybook-static', dev: { url: 'http://localhost:6006' } },
  include: ['components/**'],
  defaults: {
    strategy: 'auto',
    budget: { max: 256, warn: 128 },
    states: { include: ['default', 'hover', 'focus-visible', 'active'], mode: 'force' },
  },
  components: {
    'components-button': {
      args: { label: { as: 'text' }, iconLeading: { as: 'instance-swap' } },
      excludeCombos: [{ Variant: 'link', Size: 'lg' }],
    },
  },
  tokens: { include: 'referenced' },
  figma: { page: 'Components' },
  dcr: { scope: 'changed' },
  output: { dir: '.holotype/out' },
});
```

Story-level equivalent — authoring stays in Storybook (precedence in [16 §1](16-config.md#loading)):

```ts
export const Primary = {
  args: { variant: 'primary', label: 'Save' },
  parameters: { holotype: { args: { label: { as: 'text' } } } },
  tags: ['figma'],
};
```

## 5. Plugin information architecture <a id="plugin"></a>

Plugin window: 420×640 default, resizable (`figma.ui.resize`), Figma UI3-consistent Preact components (create-figma-plugin, D-06). Light/dark follows Figma theme (`themeColors: true`).

### 6.12 Copywriting principles

- Say what happened, why, and the one next action. No blame ("Figma can't reach…", not "You failed to…").
- Name things with the user's vocabulary: *component, variant, property, story, theme*; never *IR, Scene, nk* in UI (except in "Copy diagnostic JSON").
- Numbers over adjectives ("3 variants changed", "~2 min").
- Every warning links to its diagnostics page (`/docs/diagnostics/<CODE>`).

### 6.13 Accessibility and i18n

- Keyboard-complete (tab order, arrow-key tree, Enter/Space actions), visible focus rings, ARIA roles on tree/listbox/tabs; contrast ≥4.5:1 in both themes; never color-only status (chips carry text + icon); respects reduced motion.
- **Live regions.** A `role=status` region announces progress and results, updated at most once per 2 s. After an async step, focus moves to the result heading.
- **Text alternatives.** The structural change list is the text alternative to the visual compare. Thumbnail `alt` comes from `designerTitle`.
- **Pairing field.** `inputmode=numeric autocomplete=one-time-code`; the countdown is announced at 30 s.
- **Targets and zoom.** Targets ≥24 px; the layout reflows at 200% zoom.
- **Names.** Exclude toggles are named "Exclude ‹title› from the request".
- **Esc** closes dialogs, never the plugin.
- i18n: v1 ships **English only**, but all strings go through a message catalog (`ui/messages/en.json`) with ICU plurals so locales can be added without code changes. Generated Figma content (doc frames, labels) is English and configurable via `figma.docFrames.locale` later.

## 7. Generated Figma artifacts

### 7.1 File organization (D-22)

```
Page "Components"
  Section "Components"            ← top-level title segment
    [Doc frame: Button]  [Component set: Button]
    [Doc frame: Input ]  [Component set: Input ]
  Section "Patterns"
    …
Page "Icons"                      ← extracted/split icon components (INSTANCE_SWAP sources)
Page "Deprecated"                 ← removed stories (D-20), renamed "⚠ deprecated / Button/Old"
```

- Placement is deterministic: grid inside each Section ordered by title path; re-sync never moves sets the designer repositioned (position is not a managed property after first placement).
- Nested title segments become component name prefixes (`Forms/Input`) so the Assets panel groups them.

### 7.2 Component set layout

- Variants arranged on a 2D grid: first axis → columns, remaining axes → nested rows (story.to.design-style axis control via `defaults.grid` and `args.<name>.order`, [16](16-config.md#defaults)); default variant (story default args, Default state) is top-left (it defines `defaultVariant`, [09](09-plugin.md)).
- The set has no auto layout ([09 §7.4](09-plugin.md)). The mapper decides columns and rows; gap and padding come from `figma.grid` (24 / 32). Row/column **labels** are managed TEXT nodes in the Section, *outside* the set (so they never become variant content).

### 7.3 Documentation frame (per component)

Content is generated and managed. It is regenerated only when its inputs change, so a no-op re-sync makes 0 writes ([09 §9.3](09-plugin.md#doc-frame)):

- Title (component name), Storybook title path, description (manifest/docgen, [03](03-storybook.md)).
- Properties table: Figma property → type → source arg → values/default.
- Axis labels aligned with the set grid.
- Links: "Open in Storybook" (story URL per default story), docs page; also set as `documentationLinks` on the component set (verify, S-12-adjacent check in Phase 3).
- Last sync: the last run that **changed** this component (date, Storybook version/commit, CLI version, fidelity score).
- Footer, mode-aware ([09 §9.3](09-plugin.md#doc-frame)): library file "Managed by Holotype · synced at the last change to this component. Edits to managed layers are kept but flagged on the next sync; add notes in the Notes frame."; branch file "Branch file · `<branch>`. Edit anything: your changes become a design change request." The Notes frame is an unmanaged child frame designers can freely edit; Holotype never touches it.

### 7.4 Naming conventions

| Thing | Convention | Example |
|---|---|---|
| Component set | display name; title prefix for nesting | `Forms/Input` |
| Variant | Figma `Prop=Value, …` in axis order | `Variant=Primary, Size=Md, State=Hover` |
| Axis names | Title Case of arg name, or `name` from config | `size` → `Size` |
| Axis values | Title Case of option label (`control.labels` wins) | `primary` → `Primary` |
| Property names | Title Case; Figma appends `#id` internally | `Label`, `Show icon` |
| Layers | naming chain (`naming.layers`, [16](16-config.md#naming)) | `Button`, `Label`, `Icon / Leading` |
| Margin wrappers | `‹name› / margin` | `Avatar / margin` |
| Deprecated | `⚠ deprecated / ‹name›` | |

### 7.5 Relaunch buttons and links <a id="relaunch"></a>

Relaunch data is set on every managed component set and doc frame; the manifest `relaunchButtons` declares the commands ([09 §9.2](09-plugin.md)).

| File | Buttons (command) |
|---|---|
| library | Re-sync from Storybook (`resync`), Open in Storybook (`open`), Details (`details`) |
| branch | Review changes (`review`), Details (`details`) |

- **Re-sync** opens the plugin focused on that `sid`. Unpaired, it opens an explanation, not an error.
- **Open in Storybook** opens the Storybook URL (`figma.openExternal`) of the default story, or of the variant's story when invoked on a variant.
- **Review changes** opens Changes (§6.14). **Details** opens the Inspector (§6.17).

### 7.6 Prototype states (optional, `figma.prototypeStates`)

When a set has a `State` axis: Default → Hover `ON_HOVER` (while hovering), Default → Active `ON_PRESS`, via `setReactionsAsync` (verify API shape in Phase 3). Off by default to avoid surprising designers.

### 7.7 Status vocabulary <a id="status-vocabulary"></a>

One vocabulary for every surface. [10](10-sync.md) and [15](15-change-requests.md) link here.

**Library chips** (component browser, §6.3):

| Label | Icon | Meaning |
|---|---|---|
| Not imported | ○ | in Storybook, no `sid` in the file |
| Synced | ✓ | `irh` of every variant equals the latest capture |
| Outdated | ↻ | Storybook changed since the last apply |
| Conflict (n) | ⚠ | n managed nodes edited in Figma since the last apply (`ah` mismatch) |
| Partial | ◐ | the last apply built some variants and fell back or skipped others |
| Failed | ✖ | the last capture or apply failed (click → diagnostic) |
| Deprecated | ⌫ | `sid` no longer in Storybook; moved to the Deprecated page (D-20) |
| Locked | 🔒 | designer-owned subtree ("Keep as designed"); sync never changes it |

**Branch header states** (branch file, §5):

| Label | Icon | Meaning |
|---|---|---|
| Editing | ✎ | the designer is editing; nothing submitted since the last change |
| Submitted | ➤ | a request is saved in the file and waits for the developer |
| Changes requested | ↩ | the reviewer asked for changes (hardening) |
| Approved | ✓ | the reviewer approved this request hash (hardening) |
| Verifying | ⧗ | the developer ran `holotype verify`; results pending |
| Merged | ⇲ | `holotype branch close` ran; code is the source of truth |
| Archived | ▣ | the Figma branch was archived |
