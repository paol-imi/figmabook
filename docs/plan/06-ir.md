# 06 — Intermediate representations (package `ir`)

> **Owner.** This chapter owns every IR and document schema and every content hash (D-52). Other chapters link here and do not restate shapes.
>
> The contracts between the capture engine, the mapper and the plugin. Decisions: **D-07** (TypeBox as source of truth), **D-08** (two IRs), **D-09** (plugin = reconciler), **D-15** (fallbacks + read-back), **D-19** (identity keys).

There are three formats. All three are written in TypeBox and published as JSON Schema.

| Format | Producer → consumer | Lives where | Granularity |
|---|---|---|---|
| **Capture IR** (`CaptureDoc`) | `capture` → `mapper` | CLI cache only (`.holotype/cache/capture/…`). It is never sent to the plugin except as a debug attachment | one per **variant** |
| **Scene IR** (`SceneComponent`) | `mapper` → `plugin` | in the bundle: `components/<sid>.json` | one per **component** (set) |
| **Bundle** (`BundleManifest` + `tokens.json` + `report.json` + assets) | `cli` → `plugin` | a directory, `.holotype.zip`, or the local server stream ([02](02-architecture.md#protocol)) | one per **import run** |

Design principles:

1. **Raw facts are kept apart from decisions.** The Capture IR holds only browser facts and never makes a Figma decision. Upgrading the mapper can therefore re-derive Scene IR from cached captures without re-rendering (research: [DOM→Figma brief §1, §8](../research/dom-to-figma-brief.md)).
2. **The Scene IR is Figma vocabulary.** Every field maps 1:1 to a Plugin API property name from `@figma/plugin-typings@1.142.0`, or to a documented composite such as `fallback` or `expect`. The plugin performs no CSS interpretation (D-09).
3. **Everything is deterministic.** The same input gives a byte-identical canonical JSON and the same hashes. This is what makes caching, `irh` skipping and CI diffs possible.
4. **Assets are content-addressed** (sha256) and deduplicated across the whole bundle.
5. **Units:** all lengths are CSS px at capture DPR = 1 logical px, which equals a Figma px. Colors are normalized 0–1 floats, gamma-encoded (not linear-light), in the declared color space. Angles are in degrees, but only in Capture IR. The Scene IR uses matrices.

## 1. Shared primitives

```ts
// packages/ir/src/primitives.ts  (TypeBox: Type.Object(...) mirrors these)
export type Px = number;                       // canonicalized to 1/1000 (see §5)
export interface Rect { x: Px; y: Px; w: Px; h: Px }
export type Quad = [Px, Px, Px, Px, Px, Px, Px, Px];      // TL, TR, BR, BL (x,y) page space
export type Mat2x3 = [[number, number, number], [number, number, number]];
export type Sides<T = Px> = [T, T, T, T];                  // top, right, bottom, left (CSS order)
export type Corners<T = Px> = [T, T, T, T];                // tl, tr, br, bl (CSS order)

export type ColorSpace = 'srgb' | 'display-p3';
export interface Color { r: number; g: number; b: number; a: number; space: ColorSpace; original?: string /* CSS text, e.g. "oklch(0.7 0.1 250)" */ }

export type Severity = 'info' | 'warn' | 'error';
export interface Diagnostic {
  code: string;                 // UPPER_SNAKE with domain prefix, catalogued in 12-quality
  severity: Severity;
  message: string;
  nodeKey?: string;             // nk (Scene) or capture node id (Capture)
  variantKey?: string;          // vk
  sid?: string;
  property?: string;            // CSS or Figma property name concerned
  value?: string;               // offending value (truncated to 200 chars)
  fallback?: string;            // what we did instead
  data?: Record<string, unknown>;
}

export interface AssetRef { sha: string /* 64-hex sha256 of bytes */ }
```

## 2. Capture IR: `CaptureDoc` (one per variant)

The page-side serializer and the CDP helpers fill this in ([05](05-capture.md)). It holds **every fact any mapper stage might need**, and nothing that requires knowing Figma.

```ts
export interface CaptureDoc {
  kind: 'holotype/capture';
  captureVersion: string;                    // semver of this schema, e.g. "1.0.0"
  engine: { name: '@holotype/capture'; version: string; chromium: string; playwright: string };
  target: {
    storybookUrl: string;                    // origin + path, credentials stripped
    storyId: string; sid: string; vk: string;
    args: Record<string, JsonValue>;         // as applied (functions serialized as "[fn name]")
    globals: Record<string, JsonValue>;
    state: PseudoStateSpec | null;           // see 04/05
    viewport: { w: number; h: number }; dpr: number;
    colorScheme: 'light' | 'dark' | 'no-preference';
    rootSelector: string;                    // resolved capture root (05 §root)
  };
  timing: { renderMs: number; settleMs: number; serializeMs: number };
  rootRect: Rect;                            // union rect of root (+ portals) in page space
  root: CNode;
  portals: CNode[];                          // body-level overlays captured with the story (03 §portals)
  textStyles: Record<string, CTextStyle>;    // deduped, key = hash of style
  assets: Record<string, CAsset>;            // key = sha

  framework?: { renderer: string; boundaries: CComponentBoundary[] };   // nested component detection (D-21)
  styleSheets?: Record<string /* styleSheetId */, { sourceURL: string; sourceMapURL?: string }>;   // CSS.styleSheetAdded headers (branch mode, 05 §6.2)
  screenshot?: AssetRef;                     // Playwright screenshot of the capture root (fidelity harness, 12)
```

### 2.1 `CNode`: one node in the composed tree

```ts
export interface CNode {
  id: string;               // capture-local id "c123"; stable across probes of the same variant (data-fx-id)
  type: 'element' | 'text' | 'pseudo' | 'replaced';
  source: CSource;
  // ---- geometry (page space unless noted) ----
  borderBox: Rect;          // AABB of border quad
  quads?: { border: Quad; padding: Quad; content: Quad };   // only when transformed (CDP DOM.getBoxModel)
  untransformed?: { w: Px; h: Px };                          // offsetWidth/Height-equivalent
  transform?: Mat2x3;       // page-space affine derived from quad (05 §geometry); absent = identity
  nonAffine?: boolean;      // perspective / 3D -> rasterize
  fragments?: Rect[];       // getClientRects() for inline boxes with >1 fragment
  scroll?: { left: Px; top: Px; width: Px; height: Px };

  computed?: CComputed;     // element/pseudo only
  authored?: CAuthored;     // Typed-OM keywords + matched declarations (subset)
  // ---- content ----
  text?: CText;             // type === 'text' (a merged inline formatting context, see 05 §text)
  replaced?: CReplaced;     // img/svg/canvas/video/input...

  paint: CPaintOrder;       // stacking facts for the mapper's paint sort
}

export interface CSource {
  tag: string;                       // lowercase; pseudo: "::before"
  path: string;                      // composed path "div:0>button.btn:0>span:1" (05 §path)
  classes?: string[];                // max 16
  id?: string;
  testId?: string;                   // data-testid | data-test | data-cy
  figmaName?: string;                // data-holotype-name (alias data-figma-name); explicit hint
  figmaKey?: string;                 // data-holotype-key (alias data-figma-key); explicit nk hint
  role?: string; ariaLabel?: string;
  component?: { name: string; framework: string; boundaryId?: string };   // nearest framework component
  inShadow?: boolean; shadowHost?: boolean; slotName?: string;
  pseudo?: 'before' | 'after' | 'marker' | 'placeholder';
  nativeControl?: 'text' | 'checkbox' | 'radio' | 'select' | 'range' | 'progress' | 'meter' | 'textarea' | 'button' | 'file' | 'color' | 'date';
  srOnly?: boolean;                  // flagged visually-hidden (mapper drops)
  loc?: SourceLoc;                   // JSX location from data-holotype-loc (@holotype/vite-plugin, 05 §6.2; 15 §5.1)
}

export interface SourceLoc { file: string /* repo-relative, validated: no "..", not absolute */; line: number; col: number }

export interface CComputed {           // getComputedStyle; only non-default-relevant props kept (05 §style-diff)
  display: string; position: string; boxSizing: string; visibility: string;
  zIndex: string; opacity: number; mixBlendMode: string; isolation: string;
  overflowX: string; overflowY: string;
  padding: Sides; border: { width: Sides; style: Sides<string>; color: Sides<Color> };
  margin: Sides;
  radius: { h: Corners; v: Corners };   // elliptical radii preserved (h != v)
  outline?: { width: Px; style: string; color: Color; offset: Px };
  background: { color: Color; layers: CBackgroundLayer[]; clip: string[] };
  boxShadow: CShadow[];                 // parsed, CSS order (first = topmost)
  filter?: string; backdropFilter?: string;  // raw CSS
  clipPath?: string; maskImage?: string;
  transformOrigin?: string;
  flex?: { direction: string; wrap: string; justify: string; alignItems: string; alignContent: string; rowGap: Px; columnGap: Px };
  item?: { grow: number; shrink: number; basis: string; alignSelf: string; justifySelf: string; order: number };
  grid?: { templateColumns: string; templateRows: string; columnsPx: Px[]; rowsPx: Px[]; areas?: string;
           autoFlow: string; columnStart: string; columnEnd: string; rowStart: string; rowEnd: string;
           justifyItems: string; alignItems: string };
  insets?: { top: string; right: string; bottom: string; left: string };
  size: { width: Px; height: Px; minW: string; maxW: string; minH: string; maxH: string };
  color: Color;                          // for currentColor / SVG
  textAlign?: string; direction?: string; writingMode?: string;
}

export interface CAuthored {             // intent recovery (07 §sizing)
  width?: CLengthIntent; height?: CLengthIntent;
  minWidth?: CLengthIntent; maxWidth?: CLengthIntent; minHeight?: CLengthIntent; maxHeight?: CLengthIntent;
  flexShorthand?: string;                // authored "flex: 1" vs "1 1 auto"
  gridTemplateColumns?: string;          // authored, e.g. "repeat(auto-fill, minmax(120px, 1fr))"
  gridTemplateRows?: string;
  hasMediaQueries?: boolean;             // any @media/@container rule matched this node
  varRefs?: Record<string, CVarChain>;   // css property -> var() chain (08 §resolution)
  rules?: Record<string, CRuleRef>;      // css property -> winning rule location (branch mode only, 05 §6.2)
}

export interface CRuleRef {              // resolved to a SourceLoc by the mapper's provenance step (15 §5.2)
  selector: string;                      // as served (may be a hashed CSS-module class)
  styleSheetId: string;                  // key into CaptureDoc.styleSheets
  range: { startLine: number; startColumn: number; endLine: number; endColumn: number };
}

export type CLengthIntent =
  | { kind: 'keyword'; value: 'auto' | 'fit-content' | 'min-content' | 'max-content' | 'stretch' | 'none' }
  | { kind: 'px'; value: Px }
  | { kind: 'percent'; value: number; resolvedPx: Px }
  | { kind: 'calc'; expr: string; resolvedPx: Px }
  | { kind: 'other'; text: string };

export interface CVarChain {             // e.g. background-color: var(--btn-bg) -> var(--color-primary-500) -> #3b82f6
  property: string;                      // "background-color" | "padding-left" | ...
  authored: string;                      // the declared value text
  chain: string[];                       // ["--btn-bg", "--color-primary-500"]
  pure: boolean;                         // true iff value === resolved(last var) with no calc/color-mix/fallback-used
  fallbackUsed?: boolean;
}

export interface CBackgroundLayer {      // CSS order (first = topmost)
  image: { kind: 'url'; asset: AssetRef; natural: { w: number; h: number } }
       | { kind: 'linear'; css: string; angleDeg: number; stops: CStop[]; repeating: boolean; interpolation?: string }
       | { kind: 'radial'; css: string; shape: 'circle' | 'ellipse'; center: { x: Px; y: Px }; radii: { x: Px; y: Px }; stops: CStop[]; repeating: boolean }
       | { kind: 'conic'; css: string; fromDeg: number; center: { x: Px; y: Px }; stops: CStop[]; repeating: boolean };
  size: string; position: string; repeat: string; origin: string; clip: string; attachment: string;
}
export interface CStop { offset: number /* 0..1 along gradient line, px already normalized */; color: Color }
export interface CShadow { inset: boolean; x: Px; y: Px; blur: Px; spread: Px; color: Color }

export interface CPaintOrder {
  stackingContext: boolean;              // creates one (opacity<1, transform, z-index on positioned, ...)
  zIndex: number | 'auto';
  layer: 'negative' | 'block' | 'float' | 'inline' | 'positioned' | 'positive';
  domIndex: number;                      // order-modified document order index
}
```

## 3. Scene IR: `SceneComponent` (one per component)

The `mapper` produces this from all of a component's `CaptureDoc`s plus the planner's classifications ([04](04-variant-model.md)) and the token resolution ([08](08-tokens.md)). It is the **desired state** that the plugin reconciles towards ([09](09-plugin.md), [10](10-sync.md)).

```ts
export interface SceneComponent {
  kind: 'holotype/scene-component';
  sceneVersion: string;                       // semver, e.g. "1.0.0"
  sid: string;                                // component id (D-19)
  irh: string;                                // Merkle hash of the whole component (§6)
  meta: SceneComponentMeta;
  properties: ScenePropertyDef[];             // in display order
  variants: SceneVariant[];                   // >=1; sorted by grid position (row, col)
  setLayout: SceneSetLayout;
  docFrame?: SceneDocFrame;                   // generated documentation frame (09 §doc-frame)
  dependencies: string[];                     // sids this component instantiates (topological build order, 09)
  diagnostics: Diagnostic[];
}

export interface SceneComponentMeta {
  name: string;                               // Figma component set name ("Button")
  titlePath: string[];                        // ["Components", "Forms", "Button"] -> section placement (D-22)
  description: string;                        // markdown-ish plain text (Figma description)
  descriptionSource: 'manifest' | 'docgen' | 'parameters' | 'none';
  links: Array<{ label: string; url: string }>;   // Storybook docs/story URLs -> documentationLinks (verify, S-12)
  storyIds: string[];
  importPath?: string; exportName?: string; componentPath?: string;   // rename detection (10 §renames)
  framework?: string;
  kind: 'component-set' | 'component';        // single-variant components are a plain COMPONENT
}
```

### 3.2 Variants and set layout

```ts
export interface SceneVariant {
  vk: string;                                  // variant key (glossary)
  irh: string;                                 // Merkle hash of root subtree + variant props
  values: Record<string /* VARIANT key */, string>;    // -> Figma name "Size=Large, State=Hover"
  provenance: { storyId: string; args: Record<string, JsonValue>; globals: Record<string, JsonValue>;
                state: PseudoStateSpec | null; viewport: { w: number; h: number }; captureHash: string };
  grid: { row: number; col: number };          // position in set grid (default variant = row 0, col 0)
  root: SceneNode;                             // kind === 'component'
  fidelity?: { ssim?: number; maxBoxDelta?: Px };   // filled by harness runs (12)
  diagnostics: Diagnostic[];
}

export interface SceneSetLayout {
  // Variants are positioned inside the ComponentSetNode at x/y from SceneVariant.grid; the set has no auto layout.
  mode: 'grid';                                // only grid in v1
  columnsBy: string[];                         // VARIANT keys mapped to columns (product order)
  rowsBy: string[];                            // VARIANT keys mapped to rows
  gap: { x: Px; y: Px };                       // from figma.grid.gap (16), default 24/24
  padding: Px;                                 // from figma.grid.padding (16), default 32
  labels: boolean;                             // row/column labels: managed TEXT nodes in the Section, NOT inside the set
}
```

**Who lays out the set.** Gap and padding come from `figma.grid.gap` / `figma.grid.padding` ([16](16-config.md#figma), defaults 24 / 32). The mapper decides columns and rows (`columnsBy`, `rowsBy`, `SceneVariant.grid`); the plugin only converts `SceneVariant.grid` to x/y. The set has no auto layout. Row and column labels are managed TEXT nodes in the Section, outside the set.

### 4.1 Layout on disk

## 5. Canonical JSON

Hashing and byte-identical output require one canonical serialization. It is implemented once in `ir/canonical.ts` and used by every producer.

| Rule | Spec |
|---|---|
| Encoding | UTF-8, no BOM, `\n` line endings. Hashed form has no whitespace; files on disk may be pretty-printed, but hashes are always computed on the compact form |
| Key order | Object keys sorted by UTF-16 code unit (`Array.prototype.sort` default), recursively |
| Arrays | Order preserved. Producers must emit semantically ordered arrays: children in paint order, ranges by `start`, variants by `(row, col)`, assets by `sha`, diagnostics by `(code, nodeKey, message)` |
| `undefined` | Keys with `undefined` are omitted. `null` is kept only where a schema allows it |
| Defaults | Producers **omit** fields equal to their documented default: `visible:true`, `opacity:1`, `blendMode` default, empty arrays for `effects`/`fills` *except* when the explicit empty list is semantic. `fills: []` means "no fill", so it is kept; an absent `fills` means "leave Figma's default", which is never used for managed nodes. The schema documents every default |
| Lengths (px) | `Math.round(v * 1000) / 1000` (binding, D-52) |
| Ratios (0..1: colors, opacity, stop positions) | rounded to 1e-6 |
| Matrices | rounded to 1e-6 |
| Angles (Capture only) | rounded to 1e-3 |
| `-0` | normalized to `0`, after rounding |
| Non-finite | `NaN`/`±Infinity` are forbidden: the serializer throws `CAP_NONFINITE_VALUE`. CSS `none` max sizes are represented by omission |
| Strings | NFC-normalized; text content is kept verbatim apart from NFC |
| Numbers | serialized with the shortest round-trip representation (`JSON.stringify` of the rounded value), with no exponent below 1e21 |

The plugin main thread has no `crypto.subtle`. Hashes are **computed by producers** and travel in the documents. The plugin only *compares* them. The one exception is the applied hash `ah` ([§6](#ah)): it is computed in the main thread with a small pure-JS FNV-1a-64 over the canonical string, because cryptographic strength is not needed for edit detection.

## 6. Hashes and Merkle `irh` <a id="hashing"></a>

| Hash | Input | Length |
|---|---|---|
| asset `sha` | raw bytes | 64 hex (full) |
| `vk` | `canonical({storyId, args, globals, state, viewport})` | 16 hex |
| capture cache key | defined in [02 §5.4](02-architecture.md#capture-key) | — |
| `ah` (applied hash) | 7 per-group FNV-1a-64 hashes, see [below](#ah) | 112 hex |
| `bundleFp` | see [below](#bundle-fingerprint) | 16 hex |
| `irh` (node) | see below | 16 hex |
| `irh` (variant) | `H(variant.values, root.irh)` | 16 hex |
| `irh` (component) | `H(meta minus links' volatile parts, properties, setLayout, docFrame, variants[].irh, dependencies)` | 16 hex |
| `irh` (tokens) | `H(collections, variables minus provenance.usedBy)` | 16 hex |

A 16-hex (64-bit) prefix is enough: collisions matter only within one file and one component. The assets keep the full 256-bit hash because they are global keys.

**Node `irh`:**

```ts
irh(node) = H(canonical({
  kind, name, size, relativeTransform, xy, visible, opacity, blendMode, isMask, maskType, clipsContent,
  fills, strokes, radius, effects, layout /* minus verified */, fallback, child /* minus intent */,
  text /* minus lines when wrapMode === 'reflow' */, vector, svg, instance /* minus match */, bind, propRefs, slot,
  children: children.map(c => c.nk + ':' + c.irh)
}))
```

**Excluded** from `irh`, because a change in these must not trigger writes: `source`, `diagnostics`, `expect` (derived), `layout.verified`, `child.intent`, `instance.match`, `fidelity`, `provenance`, the `generator` versions, timestamps (there are none anywhere) and `report.json`.

**Included even though it is not written to Figma:** `fallback`. A changed fallback changes what the plugin might apply, so it must trigger a re-apply.

The plugin stores the applied `irh` per node. When `sceneNode.irh === stored.irh` and `ah` still matches ([10](10-sync.md)), the subtree is skipped with zero writes. This is how the "no-op re-sync = 0 writes" metric is met ([README §4](README.md#4-success-metrics)).

The variant and component `irh` formulas above are the only ones (variants ordered by `(row, col)`). 10 §10 links here; there is no second formula.

<a id="ah"></a>

**`ah` (applied hash, plugin main).** `normalizeGroups(readback)` from `@holotype/ir` produces 7 canonical group objects, in this order: geom, layout, paint, text, vis, bind, inst. `ah` is the concatenation of their FNV-1a-64 hashes (16 hex each, 112 chars) in that order. `base:h` uses the same function over the whole baseline snapshot. The group table below is defined here; [10 §9.1](10-sync.md#designer-edits) links to it.

The applier reads back the node after writing it (and after any verification fallback), so Figma's own normalization (float rounding, derived values) never causes a false conflict.

| Group | Properties read |
|---|---|
| `geom` | `width`, `height`; `x`, `y` only when absolute or not in auto layout; `rotation` |
| `layout` | `layoutMode`, `layoutWrap`, padding×4, `itemSpacing`, `counterAxisSpacing`, align props, sizing modes, `layoutSizingHorizontal/Vertical`, `layoutPositioning`, `min/max*`, grid props |
| `paint` | `fills`, `strokes`, stroke weights/align/dash, radii, `effects`, `opacity`, `blendMode`, `clipsContent` (paints serialized including `boundVariables`) |
| `text` | `characters`, `getStyledTextSegments(['fontName','fontSize','lineHeight','letterSpacing','fills','textCase','textDecoration','hyperlink','boundVariables'])`, `textAutoResize`, alignment, truncation |
| `vis` | `visible`, `name` |
| `bind` | `componentPropertyReferences`, `boundVariables` |
| `inst` | for instances: `mainComponent` id (`getMainComponentAsync`), `componentProperties` values |

Normalization: floats rounded to 1e-3, colors to 1e-4, then canonical JSON. A field added to readback is added to exactly one group here first.

<a id="bundle-fingerprint"></a>

**Bundle fingerprint.** `bundleFp = h16(sorted components[].irh ∥ tokens.irh ∥ config.hash)`. It is stored as `fp` / `baselineFp` in [10](10-sync.md) and [15](15-change-requests.md). It is different from `source.fingerprint` (the Storybook build fingerprint).

## 7. Versioning and migration <a id="versioning"></a>

- **Independent semver** for each of `captureVersion`, `sceneVersion`, `tokensVersion` and `bundleVersion`. A **major** is a breaking shape or semantic change; a **minor** is additive (new optional fields or new enum members guarded by a feature); a **patch** is a docs or validation fix.
- **Features gate semantics.** Any producer output that an older consumer would misapply *if it ignored the new field* must add a `features[]` entry. The plugin advertises its supported features in `x-holotype-client … features=` and `RunRequest.supportedFeatures` ([02 §4.3](02-architecture.md#protocol)); in file mode it checks the bundle's `features[]` itself. The CLI then either downgrades the output (for example, it emits `locked-lines` text as reflow and drops slots to frames with `PLAN_FEATURE_DOWNGRADED`), or refuses with `APPLY_UNSUPPORTED_FEATURE` when the feature is required by config.
- **Unknown fields:**
  - Consumers **ignore unknown fields** within a known major and **reject an unknown major** (`APPLY_IR_VERSION_UNSUPPORTED`).
  - Producers never emit unknown enum members without a feature flag.
- **Migrations:**
  - `ir/migrations/scene/<from>-<to>.ts` are pure functions. The plugin bundles migrations for the **current and previous** major.
  - Plugin data stored in files carries `v` (D-19). A plugin upgrade migrates the stored identity lazily, on first touch.
- **Capture IR** is cache-only. On a major bump the cache is invalidated because the cache key includes the major; no migration is shipped.
- **JSON Schema publication:**
  - `pnpm -F @holotype/ir build` emits `schema/{capture,scene,tokens,bundle,report}.v<major>.json` from TypeBox.
  - They are published in the npm package and on the docs site at `/schema/<name>/v<major>.json`, and referenced by `$schema` in pretty-printed files.
  - CI checks that the generated schemas are committed (a no-diff check), and runs a compatibility check: the previous minor's example documents must still validate.

## 8. Transfer budgets and chunking

| Item | Budget | Enforcement |
|---|---|---|
| One `SceneComponent` file | soft 2 MB, hard 8 MB | `PLAN_COMPONENT_TOO_LARGE` (warn/error). The planner reduces variants ([04](04-variant-model.md#budgets)) |
| UI → main `postMessage` | ≤1 MB per message | the UI splits a component into `{sid, part i/n}` chunks *per variant* (a variant is never split unless it exceeds 1 MB alone, then by subtree using `nk` paths) |
| Asset bytes | each ≤ 4096×4096 px (Figma limit), ≤ 8 MB | capture downscales and transcodes (`CAP_IMAGE_DOWNSCALED`, `CAP_IMAGE_TRANSCODED`) |
| Whole bundle | warn 100 MB, reject 200 MB compressed ([02 §5.1](02-architecture.md)); streamed. Uncompressed guard: 2 GB, compression ratio ≤100 | the local server streams NDJSON events (`component`, `asset-needed`); file import reads lazily from the zip |
| Plugin data per entry | 100 kB (Figma limit) | the registry on `figma.root` is stored as `registry:meta` + `registry:0..N-1` chunks ([10](10-sync.md#registry)) |

Assets are sent **once per file**. The plugin keeps `sha → imageHash` in the root registry, asks only for missing shas (`asset-needed`), and passes bytes as `Uint8Array` (structured clone, no base64).

|---|---|---|
| `capture` (page → Node) | no schema validation in the page. The Node side validates `CaptureDoc` with TypeBox `TypeCompiler` (compiled validators, about 1 µs per node) | always on |
| `mapper` output | full `SceneComponent` validation plus **semantic invariants**: <br>• `nk` unique within each variant <br>• children `nk` sets aligned across variants ([07 §alignment](07-mapping.md#alignment)) <br>• text ranges cover `characters` <br>• every `propRefs` key exists in `properties` <br>• every `VarRef.key` exists in `tokens.json` <br>• `fallback` present when `layout` is present <br>• sibling names unique | always on; a failure is a mapper bug: `PLAN_INVARIANT_VIOLATION` (error), and the component is skipped |
| `plugin` UI | validates `manifest.json` fully. Validates each `SceneComponent` with the **compiled validator** in the UI iframe, which is off the main thread, before forwarding | ≈5–20 ms per component (verify, S-06); never in the main thread |
| `plugin` main | trusts UI-validated input; checks only `sceneVersion` major and `features` | O(1) |
| file import | same as plugin UI, plus zip-bomb limits: total uncompressed size ≤ 2 GB, ratio ≤ 100 (`APPLY_BUNDLE_REJECTED`) | streaming |
